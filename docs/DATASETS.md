# Datasets

FireSight never bundles real fire imagery with the project. Datasets are
**user-supplied** and are read from the configured data root
(`FIRESIGHT_DATA_ROOT`, default `./data`, gitignored). Demo mode generates its
own synthetic fixtures and needs no download.

## Provenance is mandatory

Every sequence, observation and metric derived from a dataset carries a
`provenance` value. The rules FireSight enforces:

- `simulated` — generated by `firesight/demo/`. Ground truth is exact but
  synthetic; it must never be presented as real.
- `real` — imagery captured by a physical camera and supplied by the user.
- `predicted` — produced by a detector (classic heuristic or trained model).
- `heuristic` — produced by a non-learned rule (e.g. geometry thresholds).
- `manual` — entered by a human (e.g. an acknowledgement).

**Simulated evidence must never be mixed into real evaluation.** The evaluation
service refuses to score a simulated run against real ground truth and vice
versa; it returns an unavailable metric with a reason instead.

## Data root and path safety

- All user paths are resolved by `datasets/paths.py::resolve_under`, which
  rejects anything that escapes the data root (`PathSafetyError`).
- Archive extraction (`datasets/archive.py`) refuses entries with path traversal
  (`..`), absolute paths, or links pointing outside the destination
  (`UnsafeArchiveError`).
- The API's `POST /api/v1/datasets/inspect` uses the same guard, so a user
  cannot browse arbitrary filesystem locations.

## Expected layout

A single-camera sequence is a directory of images whose filenames encode a
timestamp that FireSight can verify (see `replay/discovery.py`). Frames are
never all loaded at once — the replay engine streams them.

```
data/
  <dataset>/
    <sequence_id>/
      2024-07-12_15-30-00_000000_sim-cam-a_0000.png
      2024-07-12_15-30-00_200000_sim-cam-a_0001.png
      ...
```

If a filename's timestamp cannot be parsed with a verified pattern, the frame
is rejected (`CorruptFrameError`) rather than guessed.

## Supported public datasets (helpers only)

FireSight ships **preparation helpers**, not the data. Nothing is downloaded
automatically.

### FIgLib / HPWREN (`datasets/figlib.py`)

- `validate_official_url` requires an `https` URL on the official HPWREN host.
- `download_figlib_archive` downloads a **user-supplied, officially hosted**
  archive into the data root (no bundled URL, no silent fetch).
- `build_figlib_manifest` writes a provenance manifest for a locally extracted
  sequence.

### Pyro-SDIS (`datasets/pyrosdis.py`)

- `group_frames_by_event` groups frames by event id.
- `make_event_split` performs a **deterministic event-level** split, preventing
  frame-level leakage between train and val.
- `prepare_pyrosdis` converts a locally downloaded Pyro-SDIS copy into a YOLO
  training layout.

## Synthetic demo fixtures

`firesight/demo/scenario.py::ensure_demo_sequences` renders two deterministic
sequences under `data/demo/`:

| Sequence | Camera | Frames | Plume starts | Distractor |
|----------|--------|--------|--------------|------------|
| `demo-alpha-ridge` | `sim-cam-a` (origin) | 50 @ 5 fps | frame 10 | cloud at frames 0–12 |
| `demo-bravo-ridge` | `sim-cam-b` (ENU 6000, 500) | 50 @ 5 fps | frame 16 | — |

Ground-truth source is a fixed ENU point `(3500, 2500)` about the origin
`(37.2000, -119.5000)` → `37.22252, -119.46056`. Randomness is seeded, so
regenerating produces identical frames.

## What is *not* provided

- No real fire imagery, no labels, no camera calibration files.
- No measured accuracy figures. The only "accuracy" number in the project is a
  **synthetic self-consistency check** on the demo scenario, clearly labelled as
  such in `docs/EVALUATION.md` and `docs/BUILD_STATUS.md`.
